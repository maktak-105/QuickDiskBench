# ドキュメントテンプレート統一 実施結果 v1.0

実施日: 2026-08-21
対応する計画書: なし（ユーザー指示により、Quickシリーズ5プロジェクト共通の`___appli-template`準拠状況を総点検した結果、QuickDiskBenchで見つかった重大な逸脱への対応）

## 1. 実施内容

1. **`dist/documents/`のファイル名修正**: `README.txt`(中身が日本語)・`README-en.txt`(中身が英語)という英日主従が逆転した命名を、テンプレート規則（英語版がベース名、`_jp`接尾辞、ハイフン不使用）に合わせて`readme.txt`(英語)・`readme_jp.txt`(日本語)へリネーム。`LICENSE-ja.txt`も`LICENSE_jp.txt`へリネーム。`git mv`で履歴を保持。
2. **配布用readmeへのバージョン行追加**: `readme.txt`/`readme_jp.txt`の2行目に`Distribution package v2.1.1`（配布パッケージ v2.1.1）を追加。従来はバージョン記載自体が無かった。
3. **`dist/documents/history.txt`/`history_jp.txt`の新規作成**: 従来存在しなかった配布用の変更履歴を、`HISTORY.md`/`HISTORY_jp.md`の内容から要約して作成。
4. **`document/`（単数形）フォルダの新規作成**: `spec.md`/`spec_jp.md`・`environment.md`/`environment_jp.md`・`about.md`/`about_jp.md`の日英3組6ファイルを新規作成。既存の`documents/`（複数形、GitHub公開時の注意点PDFのみ）フォルダとは別物で、そちらには触れていない。
5. **Python版とC++版の関係を明記**: `python/main.py`は独立したPython試作実装ではなく、FastAPIサーバーが同じUIをブラウザへ提供しつつ、実測定は`core/native/engine_x64.dll`（配布版exeと同じC++エンジン）を`ctypes`経由でロードして行う構成（DLL未ビルド時のみ純Python実装にフォールバック）であることを、README.md/README_jp.mdと`document/about.md`/`about_jp.md`に明記した。
6. **`core/native/QuickDiskBench.rc`にVERSIONINFOブロックを追加**: 従来はアイコン定義のみで、ビルドしたexeにファイルバージョン情報（プロパティ画面の詳細タブ）が一切埋め込まれていなかった。`FILEVERSION 2,1,1,0`等を追加。
7. **`.github/workflows/release.yml`の更新**: パッケージ対象ファイルリストをリネーム後の`readme.txt`/`readme_jp.txt`/`LICENSE_jp.txt`に更新。
8. **`README.md`/`README_jp.md`内の相互参照リンクを更新**: 旧ファイル名（`README-en.txt`、`LICENSE-ja.txt`等）への言及を新ファイル名に修正。
9. **`HISTORY.md`/`HISTORY_jp.md`に`Unreleased`エントリを新設**: 既存の`v2.1.1`エントリ（当時の正確な記録）は変更せず、今回の変更内容を新しいエントリとして追記。

## 2. 検証結果（実際に確認した内容）

- `python build_native.py`でフルビルドが成功することを確認。
- `Get-Item ... .VersionInfo`で、ビルドされた`QuickDiskBench.exe`の`FileVersion`/`ProductVersion`が実際に`2.1.1.0`になっていることを確認。
- ビルド時に再生成された`core/native/engine_x64.dll`・`QuickDiskBench_res.o`（コミット済みのビルド成果物）は今回の変更と無関係なため、`git checkout --`で元の状態に復元し、意図しない差分として残らないようにした。
- `dist/binary/`配下の新規ビルド成果物はgitignore対象であることを確認済み（差分に出ない）。

## 3. 残課題

- `git tag`には`v1.0.1`が存在するが、`HISTORY.md`/`HISTORY_jp.md`にそのエントリの記載が無い。今回は正確な変更内容が分からないため触れていない。
- 今回の変更はコミット・プッシュ・バージョンタグ付けは行っていない（ドキュメント総点検の一環としてローカルの作業ツリーを修正した段階）。
- 他4プロジェクト（QuickFolderSize・QuickFileCopy・Quick7Zip・QuickMarkPDF）との横断的な整合性確認は、それぞれ個別のExploreエージェント調査結果を参照。QuickFolderSizeも同様の重大な逸脱（`readme-jp.txt`命名違反、`document/`の`_jp`版欠落、`HISTORY.md`欠如）があり、次に対応する。
