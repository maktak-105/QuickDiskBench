# フォルダ構成テンプレート再編成 計画書 v1.0

作成日: 2026-09-19
対象バージョン: v2.2.1

## 1. 目的・背景

`quick-app-template` が最新仕様（v2.0.0）に更新されたことに伴い、QuickDiskBench のフォルダ構成・ドキュメント配置・ビルド構成を最新の標準規格に再編成する。
あわせて、テンプレート標準である「HTMLの自己完結EXE埋め込み（RCDATA化）」と「配布ZIPのフラット化（不要なindex.htmlの同梱除外）」を実施する。

## 2. 現状

- ソースコードが `core/native/`、`templates/`、`static/` に分散している。
- ビルド生成物である `core/native/engine_x64.dll`、`QuickDiskBench_res.o` が Git 管理されている。
- ビルドスクリプト（`build_native.py`、`bundle_html.py`、`requirements.txt`）がルート直下に散らばっている。
- ドキュメントが `document/`（開発文書）、`dist/documents/`（配布用テキスト）、`documents/`（PDF）に分散している。
- ビルド成果物が `dist/binary/` という階層下に生成され、`index.html` も外部ファイルとしてEXEと同階層に配置して読み込んでいる。
- 配布ZIPにも `index.html` が同梱されている。

## 3. 変更方針

1. **フォルダ構成の標準化 (`src/`, `scripts/`, `docs/`)**:
   - `core/native/` → `src/app/`（`main_gui.cpp`等）、`src/cli/`（`main_cli.cpp`）、`src/engine/`（`engine.cpp`）
   - `templates/`, `static/` → `src/ui/`（`index.html`, `css/`, `js/`, `img/`）
   - `build_native.py`, `bundle_html.py`, `requirements.txt` → `scripts/`（`build.py`, `bundle_html.py`, `build.bat`, `requirements.txt`）
   - `benchmark-all-drives.ps1` → `scripts/benchmark-all-drives.ps1`
   - `document/` → `docs/`
   - `dist/documents/` → `docs/distribution/`
   - `documents/*.pdf` → `docs/`
2. **コミット済みバイナリの追跡解除**:
   - `core/native/engine_x64.dll`, `QuickDiskBench_res.o` を `git rm`。
3. **HTML自己完結埋め込み（RCDATA化）**:
   - `scripts/bundle_html.py` で `src/ui/` から `build/intermediate/index.html` を生成。
   - `src/app/QuickDiskBench.rc` に `201 RCDATA ...` を追加。
   - `src/app/main_gui.cpp` で RCDATA リソースから HTML 文字列を取得して `NavigateToString` する処理を追加（リソースが見つからない場合はファイル読み込みにフォールバック）。
4. **ビルドスクリプトと出力のフラット化**:
   - `scripts/build.py`: 出力先を `dist/` 直下に変更し、中間生成物は `build/intermediate/` に配置。
   - `scripts/build.bat` を配置。
   - 配布ZIPから `index.html` を除外。
5. **ドキュメント・CIの整合性追従**:
   - `docs/` 配下、`docs/distribution/` 配下、ルートの `README.md`, `README_jp.md` 等のパス記述を新構成に更新。
   - `.github/workflows/release.yml` を新構成に合わせて更新。
   - `.gitignore` を更新。

## 5. 影響範囲

- ビルド手順が `scripts\build.bat` または `python scripts/build.py` に統一される。
- 配布ZIPが `dist/` 直下の成果物と `docs/distribution/` のテキストのみで構成され、不要な `index.html` が同梱されなくなる。

## 6. 検証方法

1. `python scripts/build.py` によるネイティブビルドの成功確認。
2. 生成された `dist/QuickDiskBench.exe` が単体で（外部 `index.html` なしで）起動し、UI が表示されることの確認。
3. `dist/QuickDiskBench_cli.exe --help` の動作確認。
4. `python python/browser/main.py` のパス解決確認。
5. `git status` で余分な追跡漏れや差分がないことの確認。

## 7. リスク・懸念

- リソース埋め込みHTMLの文字コード（UTF-8）処理による文字化けリスク → ワイド文字列変換を適切に行う。
- パス変更に伴うCI/ビルドのパス切れ → ワークフローおよびスクリプト内のすべての参照パスを精査して更新。
